Package io.spine.delivery.server

Class DeliveryShardRegistry

  • All Implemented Interfaces:
    io.spine.logging.WithLogging 
    
public final class DeliveryShardRegistry
 implements WithLogging

    The registry of the shard indexes along with the worker identifiers, which process the messages corresponding to each index.

    The session records are kept in a ShardSessionStore, which several Delivery servers may share. Every read-then-write of a record is a compare-and-set against the record that was read, so each change is atomic across all those servers.

        DeliveryShardRegistry(ShardSessionStore store, Duration processingTimeout)

        Creates a new DeliveryShardRegistry backed by the given store.

        The given processingTimeout is used to determine whether a session is stale. Stale sessions are released automatically. Pass Durations.ZERO to disable the stale-check. In this case all picked up sessions will always be considered active until explicitly released by a worker.

      • pickUp

         ShardProcessingSession pickUp(ShardIndex index, WorkerId worker)

        Picks up the shard at a given index to process.

        This action is exclusive across all the servers that share the store, with the exception below: a single shard may be served by a single worker at a given moment of time.

        The exclusivity is per worker, and clients choose the worker IDs. An ID must stay the same across a restart for the worker to recover its shards. Each unit of work that may run concurrently needs its own ID, because pick-ups under one ID never exclude each other.

        In case of a successful operation, an instance of ShardProcessingSession is returned. There are three options when it is successful:

        • There is no worker associated with the requested shard.
        • The requested shard is already held by the given worker. The worker gets the shard again, and its session is renewed. A worker asks for a shard it holds when it loses track of its session, for example, when the reply to its pick-up is lost, when its release fails, or when it restarts after a failure.
        • The requested shard is already held by another worker, but its processing time reached processingTimeout. Such a session is considered stale and released automatically.

        In case the shard at a given index is already picked up by another worker and has not reached processing timeout, a ShardAlreadyPickedUp is thrown.

        The exclusivity has one exception: a store shared by servers that a network split divides may let each part of them pick the same shard.

        Parameters:
        index - the index of the shard to pick up for processing
        worker - the identifier of the worker for which to pick the shard
        Returns:

        the session of shard processing

      • releaseShard

         ReleaseOutcome releaseShard(ShardIndex index, WorkerId worker)

        Releases the shard under the given index, if the given worker holds it.

        Clears the worker of the shard's record only if the given worker holds the shard, and leaves the session of another worker intact. So a worker whose session became stale cannot release the shard that another worker picked after that, even by a late or a repeated request.

        The release ends only the session it found when it first read the record. If the given worker picked the shard again after that, its newer session is left intact. So a release that stalls after it read the record cannot end the session that its worker started meanwhile. A release that reads the record only after the worker picked the shard again finds the newer session, and ends it.

        Parameters:
        index - the index of the shard to release
        worker - the worker that releases the shard
        Returns:

        the outcome of the release
